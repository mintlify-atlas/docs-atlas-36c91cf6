The Appointments module is the operational heart of BeautySalon. Every booking created here is persisted to the `appointments` table in Supabase and linked to both a `services` row and a `staff` row via foreign keys. The page offers a filterable list view of all appointments, a slide-in creation form with smart client lookup, and inline status-transition buttons so staff can progress a booking from its initial scheduled state all the way through to completion.

---

Every appointment row carries a `status` string column. The valid values and their UI representations are defined in the `statusLabels` map inside `AdminAppointments.tsx`:

<Warning>
  All status update operations — as well as appointment creation — are **disabled in demo mode**. Calling `updateStatus()` or `handleCreate()` while `isDemo === true` triggers a toast notification (`"No disponible en modo demo"`) and returns immediately without touching Supabase. Explore the [live demo](https://beautysalonsaas.netlify.app) to see the read-only view.

Five filter chips sit above the appointment list. Selecting one re-runs the React Query fetch with the chosen status value (or no filter for "Todas"):

The Supabase query that drives the list:

```typescript
let query = supabase
  .from("appointments")
  .select("*, services(name, price_min, price_max), staff(name)")
  .order("appointment_date", { ascending: false })
  .order("appointment_time", { ascending: false });

if (filter !== "all") query = query.eq("status", filter);

const { data } = await query.limit(100);
```

## Status Transition Buttons

Each appointment card renders action buttons conditionally based on its current `status`. All transitions call the same `updateStatus` function:

```typescript
const updateStatus = async (id: string, status: string) => {
  if (isDemo) { toast.info("No disponible en modo demo"); return; }

  const { error } = await supabase
    .from("appointments")
    .update({ status })
    .eq("id", id);

  if (error) { toast.error("Error al actualizar"); return; }

  toast.success(`Cita ${statusLabels[status]?.label.toLowerCase()}`);
  queryClient.invalidateQueries({ queryKey: ["admin-appointments"] });
  queryClient.invalidateQueries({ queryKey: ["admin-stats"] });
};
```

After a successful update, both the `admin-appointments` and `admin-stats` React Query caches are invalidated so the list and the dashboard KPIs both reflect the change immediately.

### NIT/Cédula Debounced Lookup

The lookup fires after the user has typed at least four characters and pauses for 600 ms:

```typescript
const handleNitChange = (value: string) => {
  setFormData(prev => ({ ...prev, nit_cedula: value }));
  setClientFound(false);
  if (debounceRef.current) clearTimeout(debounceRef.current);

  if (value.trim().length >= 4) {
    debounceRef.current = setTimeout(() => lookupClient(value), 600);
  }
};

const lookupClient = useCallback(async (nit: string) => {
  if (!nit.trim() || isDemo) { setClientFound(false); return; }
  setLookingUp(true);
  try {
    const { data } = await supabase
      .from("clients")
      .select("*")
      .eq("nit_cedula", nit.trim())
      .maybeSingle();

    if (data) {
      setFormData(prev => ({
        ...prev,
        client_name: data.name || "",
        client_email: data.email || "",
        client_phone: data.phone || "",
        direccion: data.direccion || "",
      }));
      setClientFound(true);
      toast.success("Cliente encontrado");
    } else {
      setClientFound(false);
    }
  } catch {
    setClientFound(false);
  } finally {
    setLookingUp(false);
  }
}, [isDemo]);
```

A spinning `Loader2` icon appears inside the NIT input while the request is in flight.

## Client Upsert on Save

When `handleCreate` runs, it first **upserts** the client record into the `clients` table using `nit_cedula` as the conflict key. This means the client database is automatically kept up to date every time you create an appointment — no separate client management step required:

```typescript
// Upsert client before inserting the appointment
if (formData.nit_cedula.trim()) {
  await supabase.from("clients").upsert(
    {
      nit_cedula: formData.nit_cedula.trim(),
      name: formData.client_name,
      email: formData.client_email || null,
      phone: formData.client_phone || null,
      direccion: formData.direccion || null,
    },
    { onConflict: "nit_cedula" }
  );
}
```

The appointment is then inserted into the `appointments` table:

```typescript
const { error } = await supabase.from("appointments").insert({
  nit_cedula: formData.nit_cedula || null,
  client_name: formData.client_name,
  direccion: formData.direccion || null,
  client_email: formData.client_email || null,
  client_phone: formData.client_phone || null,
  service_id: formData.service_id || null,
  staff_id: formData.staff_id || null,
  appointment_date: formData.appointment_date,
  appointment_time: formData.appointment_time,
  notes: formData.notes || null,
});
```

On success the form closes, the filter resets, and both the `admin-appointments` and `admin-stats` query caches are invalidated.

<Tip>
  If `clientFound` is `true` when you open the form for a returning client, an extra **"Actualizar Cliente"** button appears at the bottom of the form. Clicking it performs a standalone upsert against the `clients` table without creating a new appointment, letting you correct a phone number or address on the fly.
</Tip>

## Staff Availability Indicator

The staff dropdown is backed by a separate `staffDayAppointments` query that re-executes whenever the selected `appointment_date` changes and auto-refreshes every 15 seconds:

```typescript
const { data: staffDayAppointments } = useQuery({
  queryKey: ["staff-day-appointments", formData.appointment_date],
  queryFn: async () => {
    const { data } = await supabase
      .from("appointments")
      .select("staff_id, status")
      .eq("appointment_date", formData.appointment_date)
      .in("status", ["pending", "confirmed"]);

    const map: Record<string, { total: number; busy: boolean }> = {};
    (data || []).forEach(a => {
      if (!a.staff_id) return;
      if (!map[a.staff_id]) map[a.staff_id] = { total: 0, busy: false };
      map[a.staff_id].total++;
      if (a.status === "confirmed") map[a.staff_id].busy = true;
    });
    return map;
  },
  enabled: !!formData.appointment_date,
  refetchInterval: 15000,
});
```

The resulting map drives the option label for each staff member in the dropdown — giving the receptionist a real-time view of workload before assigning a booking.
