The Services module is where you define everything your salon offers. Each service record specifies a name, a price range in Colombian Peso (COP), a duration window in minutes, an optional buffer time between appointments, a consultation requirement flag, and an active/inactive toggle. Services are grouped into categories drawn from the `staff_categories` table, and the category filter chips on this page let you narrow the list instantly without a round-trip to Supabase.

---

## Service Data Model

The `services` table schema (from `src/integrations/supabase/types.ts`) defines the following columns:

<ResponseField name="id" type="string (uuid)">
  Auto-generated primary key.
</ResponseField>
<ResponseField name="name" type="string" required>
  Display name of the service, e.g. `"Keratina"` or `"Manicure clásica"`.
</ResponseField>
<ResponseField name="description" type="string | null">
  Optional free-text description shown in the service list and booking flow.
</ResponseField>
<ResponseField name="price_min" type="number" required>
  Minimum price in COP. Also used as the revenue figure on the Dashboard KPI for completed appointments.
</ResponseField>
<ResponseField name="price_max" type="number">
  Maximum price in COP. Defaults to `price_min` if not provided. When `price_min === price_max`, the UI shows a single value; otherwise it renders a range (e.g. `$25.000 – $80.000`).
</ResponseField>
<ResponseField name="duration_min" type="number" required>
  Minimum service duration in minutes. Default `30`.
</ResponseField>
<ResponseField name="duration_max" type="number">
  Maximum duration in minutes. Defaults to `duration_min`. Displayed as `"45 min"` or `"60–90 min"`.
</ResponseField>
<ResponseField name="buffer_time" type="number">
  Cleanup or preparation minutes added after the service ends before the slot is considered free. Default `0`. Body-treatment services (e.g. massages) typically carry a value of `10`.
</ResponseField>
<ResponseField name="category_id" type="string (uuid) | null">
  Foreign key to `staff_categories.id`. Determines which category chip the service appears under.
</ResponseField>
<ResponseField name="requires_consultation" type="boolean">
  When `true`, an orange **Consulta** badge appears on the service card, signalling that the client must book a consultation before the service is performed.
</ResponseField>
<ResponseField name="is_active" type="boolean">
  Controls visibility in the appointment booking form. Inactive services are hidden from the `service_id` dropdown but remain in the admin catalog with a grey **Inactivo** badge.
</ResponseField>
<ResponseField name="gender" type="string">
  Audience flag, hardcoded to `"all"` in the current save payload, reflecting the unisex nature of the salon.
</ResponseField>

## Price and Duration Formatting

All monetary values are rendered in Colombian Peso using the `es-CO` locale with zero decimal places. Duration is shown as a single value when `min === max`, or as a range otherwise:

```typescript
const fmtCOP = (v: number) =>
  v.toLocaleString("es-CO", {
    style: "currency",
    currency: "COP",
    minimumFractionDigits: 0,
    maximumFractionDigits: 0,
  });

const formatPrice = (min: number, max: number) =>
  min === max ? fmtCOP(min) : `${fmtCOP(min)} – ${fmtCOP(max)}`;

const formatDuration = (min: number, max: number) =>
  min === max ? `${min} min` : `${min}–${max} min`;
```

Example output: `$150.000 – $350.000` and `120 min` for the Keratina service.

## Category Filter Chips

A row of pill buttons appears above the service list. Clicking any chip sets `filterCategory` to the corresponding `staff_categories.id`, which drives a client-side filter — no additional network request is made:

```typescript
const filteredServices = services?.filter(
  s => filterCategory === "all" || s.category_id === filterCategory
);
```

The **Todos** chip (default) disables filtering and shows all services regardless of category.

## Creating a Service

Clicking the **Agregar** button in the header opens an inline form panel above the list. The form in create mode includes a `<datalist>` on the name field that autocompletes from existing service names in the catalog. When the user selects an existing name from the suggestions, the category field is automatically populated to match:

```tsx
<input
  list="service-options"
  value={name}
  onChange={(e) => {
    const val = e.target.value;
    setName(val);
    const match = services?.find(s => s.name === val);
    if (match?.category_id) {
      setCategoryId(match.category_id);
    }
  }}
  placeholder="Escriba o seleccione un servicio"
/>
<datalist id="service-options">
  {services?.map(s => <option key={s.id} value={s.name} />)}
</datalist>
```

<Note>
  The `<datalist>` autocomplete is **only shown in create mode**. When editing an existing service, the name field renders as a plain `<input>` without suggestions, preventing accidental name collisions.
</Note>

## The `handleSave` Payload

On save (create or update), `handleSave` constructs the following payload and sends it to Supabase. The `gender` field is always `"all"`, reflecting the salon's unisex positioning:

```typescript
const payload = {
  name: name.trim(),
  description: description.trim() || null,
  price_min: Number(priceMin),
  price_max: Number(priceMax) || Number(priceMin),
  duration_min: Number(durationMin),
  duration_max: Number(durationMax) || Number(durationMin),
  category_id: categoryId || null,
  gender: "all",
  requires_consultation: requiresConsultation,
  buffer_time: Number(bufferTime),
  is_active: isActive,
};

if (editing) {
  // UPDATE existing row
  const { error } = await supabase
    .from("services")
    .update(payload)
    .eq("id", editing.id);
} else {
  // INSERT new row
  const { error } = await supabase
    .from("services")
    .insert(payload);
}
```

Both branches invalidate `["admin-services"]` and `["admin-stats"]` query caches on success, so the service list and dashboard KPIs update immediately.

## Toggling Active Status

A service can be made inactive by editing it and unchecking the **Activo** checkbox, then saving. Inactive services:

- Show a grey **Inactivo** badge in the admin service list.
- Are excluded from the `services` dropdown in the appointment creation form (the query adds `.eq("is_active", true)`).
- Are excluded from the **Servicios** KPI count on the Dashboard (same `is_active = true` filter).

<Tip>
  Deactivating a service rather than deleting it preserves the historical link between past `appointments` rows and the `service_id` foreign key. Deletion removes the service record entirely and could leave orphaned appointment rows without a service name.
</Tip>
