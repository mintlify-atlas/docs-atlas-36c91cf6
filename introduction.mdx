Running a modern beauty salon means juggling appointments, tracking staff availability, pricing a broad menu of services, and keeping a clean record of every client visit — all while staying focused on the actual work. BeautySalon is an open-source, full-stack SaaS application built to handle all of that in one place. It ships with a polished admin panel that connects directly to a Supabase backend, giving salon owners real-time visibility into their operations from any device without the cost or complexity of proprietary salon software.

## The Problem It Solves

Small-to-medium salon owners typically wrestle with one of two bad options: paper-and-spreadsheet chaos, or expensive all-in-one platforms that lock data in proprietary silos. BeautySalon offers a third path — a self-hosted, open-source platform you can deploy in minutes to your own Supabase project, with full ownership of the database and the freedom to modify every line of code.

## Tech Stack

BeautySalon is built on a modern, well-supported open-source stack with no proprietary dependencies:

| Layer | Technology |
|---|---|
| Frontend framework | React 18 + TypeScript |
| Build tool | Vite 5 |
| Backend / database | Supabase (PostgreSQL + Auth + RLS) |
| Data fetching | TanStack Query v5 |
| Routing | React Router v6 |
| UI components | Tailwind CSS + shadcn/ui (Radix UI primitives) |
| Charts | Recharts |
| Forms | React Hook Form + Zod |
| Notifications | Sonner |
| Date utilities | date-fns |

## Architecture Overview

BeautySalon follows a straightforward single-page application architecture. The React frontend runs entirely in the browser and communicates with Supabase over its auto-generated REST and Realtime APIs. There is no custom server-side layer — Supabase handles authentication, row-level authorization, and data persistence. TanStack Query manages all remote state on the client, providing caching, background refetching, and optimistic updates out of the box.

```
Browser (React SPA)
  └─ React Router v6          ← URL-based routing, protected routes
  └─ AuthProvider (useAuth)   ← Supabase session + demo flag
  └─ TanStack Query           ← Data fetching & cache
       └─ Supabase JS Client  ← REST / Realtime to Supabase
            └─ PostgreSQL     ← Tables: appointments, services, staff,
                                        clients, staff_categories
            └─ Supabase Auth  ← Email/password sessions + JWT
            └─ RLS Policies   ← Per-table row-level authorization
```

The entire admin panel lives under the `/admin/*` route, which is wrapped in a `ProtectedRoute` component that redirects unauthenticated visitors to the login page. Entering Demo Mode bypasses Supabase entirely and injects a synthetic user into the auth context.
